# PDF Contigo 2.4 beta 7

**Corrección del proceso de conexión de IA.** Se mantienen las 29 herramientas, los seis proveedores y el procesamiento de PDF en el dispositivo.

## Qué cambia

- El proveedor se elige explícitamente: Gemini ya no aparece preseleccionado. OpenAI se identifica también como creador de ChatGPT.
- Corregir el proveedor conserva la clave que has pegado. Un evento repetido del selector no reinicia la clave ni el modelo.
- Un evento de cierre tardío no vacía una configuración que ya se ha vuelto a abrir.
- «Clave introducida» confirma que el campo tiene datos, sin mostrar la clave. No significa que el proveedor la haya validado.
- Los mensajes distinguen campo vacío, clave incompleta o enmascarada, espacios y rechazo del proveedor. Tras un error puedes corregir y volver a conectar sin pegarla otra vez.
- Si un formato reconocible de clave parece de otro proveedor, la petición se bloquea antes de salir. Puedes seleccionar el proveedor correcto y confirmar. Las claves de formato desconocido siguen admitidas y no se atribuyen automáticamente a ninguna empresa.
- Se detectan también modelos reconocibles de otro proveedor. Google `API_KEY_INVALID` en una respuesta HTTP 400 se explica como un rechazo de autenticación.

No hay pruebas automáticas con varios proveedores, reintentos ni cambios de cuenta. Las claves siguen solo en memoria. Conectar en modo automático consulta el catálogo, sin generar texto ni enviar documentos; no comprueba saldo ni permiso de generación. OpenAI API y la suscripción a ChatGPT son servicios distintos.

## Actualizar

Recarga la web y comprueba **Versión 2.4 beta 7**. En Windows/Mac descarga y extrae el ZIP actualizado completo. Abre **Configurar IA**, elige **OpenAI (creador de ChatGPT)** si tu clave es de OpenAI, pégala y pulsa **Conectar con OpenAI**.

## Verificación

Las pruebas reproducen los borrados de clave por cambio de proveedor y por un evento de cierre pendiente; ambos casos fallaban antes de la corrección y ahora pasan. Se cubren también el pegado sin evento de entrada, reintentos tras un rechazo, selección de modelo y el recorrido OpenAI hasta un informe con citas. Los formatos incompatibles se rechazan con cero peticiones.

Se utilizan claves ficticias y respuestas simuladas, sin consumir APIs. No se ha probado la cuenta del usuario ni se presenta esta comprobación de DOM como una prueba en Android, iOS, Windows o Mac reales. Los bloqueos de red o CORS y los permisos/saldo de cada cuenta siguen dependiendo del proveedor. En escritorio se conserva el conector que se ejecuta en el propio ordenador, sin servidor compartido de PDF Contigo.

GitHub Actions sigue publicando los ZIP directamente en Releases, sin duplicarlos como artefactos temporales ni crear cachés npm.
